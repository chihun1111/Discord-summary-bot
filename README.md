# Discord 채팅 인덱싱·검색·요약 봇

Python 기반 시작용 구현입니다. **허용한 채널의 원문을 로컬 SQLite에 저장하고, 한국어 키워드로 검색하며, 필요한 대화만 AI에 전달해 요약/답변을 생성**합니다.

소스와 테스트를 제공하며, Hermes 서버의 관리 웹 배포 설정은 `deploy/HERMES.md`에 기록합니다. 디스코드 토큰은 운영자가 자신의 환경에 설정해야 합니다.

## 1. 구현 범위

| 기능 | 동작 |
|---|---|
| 실시간 수집 | 지정 서버의 허용된 일반 텍스트 채널만 수집 |
| 인덱싱 | 원문 + 전체 단어/2글자 bigram + SQLite FTS5 |
| 키워드 검색 | 기간·채널 범위, 검색 시 접근 권한 확인, 상위 8개와 원문 링크 |
| 채널 요약 | 최근 1~168시간, 핵심 논의·결정·할 일·미해결 쟁점 |
| 질문 답변 | `/ask` 검색 답변 및 전용 질문 채널의 공개 스레드 대화 |
| 과거 기록 | `/index`로 페이지별 수집, 더 오래된 기록을 위한 커서 반환 |
| 변경 반영 | 메시지 수정·일괄/개별 삭제 이벤트, 원문/검색 인덱스 동시 갱신 |
| 개인정보 | 수집 제외·기존 본인 기록 삭제, 보관기간 정리, 슬래시 명령은 요청자 전용 결과 |
| 비용 제어 | AI 기본 비활성, 일일 API 호출 수 제한, 사용자별 쿨다운, AI 요청 직렬 처리 |

단일 서버·단일 봇 프로세스·로컬 디스크용 MVP입니다. DM, 연령 제한(NSFW) 채널, 스레드(공개/비공개), 포럼 게시물, 음성, 이미지·첨부파일 내용, 봇·웹훅 메시지는 인덱싱 대상이 아닙니다. 별도로 지정한 질문 채널에서는 봇이 만든 공개 스레드에서 대화할 수 있습니다. 외부 링크를 따라가거나 원문의 명령을 실행하지 않습니다.

**이 버전은 키워드 검색이며 벡터/의미 검색이 아닙니다.** `/ask`도 `query` 핵심어가 필요합니다. 뜻이 비슷하지만 단어가 다른 대화까지 찾아야 한다면 향후 별도 임베딩 검색을 추가해야 합니다.

## 2. 구조

```text
Discord Gateway / 과거 메시지 API
        ↓ 허용 서버·채널·보관기간·수집 제외 확인
SQLite messages + FTS5 검색 인덱스
        ├─ /search → 권한 범위 내 검색 → 원문 재확인 → 원문 링크
        └─ /ask → 검색 + 같은 채널 주변 문맥 → 원문 재확인 → AI 답변

/summary → 선택 채널의 최신 원문 조회·인덱스 보정
         → 길이에 따라 분할 요약 → 통합 요약 → 원문 링크
```

요약은 관련도 상위 검색 결과만으로 하루 전체를 요약하지 않습니다. 선택한 채널의 시간 범위를 직접 조회합니다. 반면 `/ask`는 제한된 검색 근거에 대한 답변입니다.

### 한국어 검색 방식

예를 들어 `배포일정을`은 개념적으로 다음 단위를 인덱싱합니다.

```text
전체 단어: 배포일정을
두 글자 단위: 배포 / 포일 / 일정 / 정을
```

실제 FTS 토큰은 안전한 ASCII 인코딩을 사용합니다. 따라서 `배포`, `일정`, `배포일정`으로 해당 원문을 찾을 수 있습니다. 여러 검색 단어는 AND 조건이며, 한 글자는 전체 단어가 일치할 때만 찾습니다. 대소문자와 유니코드 호환 문자를 정규화합니다.

FTS5의 기본 trigram 방식은 3글자 미만의 full-text 검색에 제약이 있으므로 이 구현에서는 직접 만든 bigram 토큰을 사용했습니다. 형태소 분석이나 동의어 추론은 수행하지 않습니다. [S3]

## 3. 디스코드 설정

1. Discord Developer Portal에서 애플리케이션과 Bot을 만들고 Bot Token을 발급받습니다. 토큰은 공개 채널·깃 저장소·질문 메시지에 붙여넣지 마세요.
2. Bot 설정에서 **Message Content Intent**를 켭니다. 코드는 해당 intent를 요청합니다. 검증된 앱 등에서는 별도의 승인 조건을 확인해야 합니다. [S1]
3. 서버 설치(Guild Install)에 `bot`, `applications.commands` 범위를 설정합니다. 개인 계정 전용 설치가 아니라 서버에 설치하세요. [S4]
4. 대상 채널에서 봇에 **View Channel**, **Read Message History**, **Send Messages** 권한을 줍니다. 관리자 권한은 필요하지 않습니다. 기존 메시지를 읽으려면 채널 보기 및 기록 읽기 권한이 필요합니다. [S2]
5. Discord의 개발자 모드를 켜서 서버 ID와 수집할 채널 ID를 복사합니다. 이 프로젝트는 수집할 채널을 자동으로 전체 선택하지 않습니다.

`/index` 실행자는 서버 관리(Manage Server) 권한이 있어야 합니다. 명령 표시용 기본 권한뿐 아니라 실행 시 권한 검사도 적용했습니다. [S5]

## 4. 로컬 실행

Python 3.11 이상과 FTS5가 포함된 SQLite 환경을 대상으로 작성했습니다. 검증 환경과 범위는 `TEST_REPORT.md`에 기록합니다.

### macOS / Linux

```bash
cd discord-chat-index-bot
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

### Windows PowerShell

```powershell
cd discord-chat-index-bot
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

`.env`에 본인의 값을 넣습니다.

```dotenv
DISCORD_TOKEN=실제_봇_토큰
DISCORD_GUILD_ID=실제_서버_ID
INDEX_CHANNEL_IDS=실제_수집채널_ID1,실제_수집채널_ID2
QUESTION_CHANNEL_IDS=실제_질문채널_ID
RETENTION_DAYS=30
ALLOW_EXTERNAL_LLM=false
```

수집 범위·보관기간·외부 전송 여부를 서버 구성원에게 먼저 공지하세요. **AI 없이도 수집·검색·인덱싱은 사용할 수 있습니다.** 요약과 질문 답변을 활성화할 때만 다음을 설정합니다.

```dotenv
ALLOW_EXTERNAL_LLM=true
GEMINI_API_KEY=실제_API_키
GEMINI_MODEL=gemini-3.5-flash-lite
LLM_DAILY_CALL_LIMIT=50
```

기본 모델은 환경변수로 교체할 수 있습니다. 선택한 Google 프로젝트에서 사용할 수 있는 Gemini 모델인지 확인하세요. 기본 모델의 계정별 접근과 실제 출력 토큰 제한은 실연결에서 확인해야 합니다. 모델 정보는 [S7]을 참고하세요.

실행:

```bash
python -m chatbot.bot
```

Windows에서는 다음처럼 가상환경의 Python을 직접 실행할 수 있습니다.

```powershell
.\.venv\Scripts\python.exe -m chatbot.bot
```

봇이 실행 중인 PC나 서버가 꺼지면 수집도 중단됩니다. 재접속 뒤 최근 기록 보정은 있지만 장기간 중단 구간을 무제한 자동 복구하지는 않습니다.

## 5. 명령어 사용

아래는 Discord 슬래시 명령 입력 예시입니다. `channel`에는 실제 채널을 선택하세요.

```text
/index channel:#개발 days:30 limit:1000
/search query:배포 days:7
/search query:배포 일정 days:30 channel:#개발
/summary hours:24 channel:#개발
/ask question:배포 날짜가 언제로 정해졌어?
/ask question:C언어 strlen 설명해줘
/ask question:배포 날짜가 언제로 정해졌어? query:배포 days:30 channel:#개발
/status
/privacy action:info
/privacy action:optout
/privacy action:optin
```

`/search`와 `/ask`에서 채널을 생략하면 요청자가 읽을 수 있는 허용 채널 전체가 대상입니다. `/summary`에서 생략하면 현재 일반 텍스트 채널을 사용합니다. 이 슬래시 명령들의 결과는 요청자에게만 보이는 ephemeral 응답입니다. 질문 채널의 자동 스레드 답변은 해당 채널 구성원에게 공개됩니다.

### 과거 메시지 전체를 채우는 방법

`/index`는 한 번에 원문 최대 1,000개를 확인합니다. 봇·내용 없는 메시지도 조회 개수에는 들어가므로 실제 저장 건수는 더 작을 수 있습니다.

결과에 `next_before`가 있다면 같은 채널·기간을 유지하고 다음 페이지를 실행합니다.

```text
/index channel:#개발 days:30 limit:1000 before:반환된_메시지_ID
```

더 오래된 기록이 없다는 안내가 나올 때까지 반복합니다. `days`는 `RETENTION_DAYS`를 넘지 않습니다. 90일 기록을 보관하려면 설정도 90으로 바꾼 뒤 재시작해야 합니다. 이미 삭제되어 Discord API로 조회할 수 없는 원문은 복구하지 않습니다.

### 요약 범위와 누락 표시

`/summary hours:24`는 달력상의 '오늘'이 아니라 최근 24시간입니다. 지정한 기간의 원문을 페이지 끝까지 조회하며 500개에서 멈추지 않습니다. AI 입력은 전처리 후 최대 168,000자이며, 넘으면 최근 원문을 우선하고 **부분 요약**임을 표시합니다. 42,000자 이하는 한 번, 그보다 길면 분할 요약 후 통합하므로 한 명령이 여러 API 호출을 사용할 수 있습니다.

전처리는 저장 원문을 바꾸지 않습니다. 독립적인 인사·웃음과 같은 사람이 2분 이내 연속으로 보낸 중복만 요약 입력에서 생략합니다. 답글과 답글 대상, 서로 다른 사람의 발언, 동의·반대·변경 내용은 유지합니다. 인사·반응·반복 횟수나 원문을 요청하면 생략하지 않습니다. 반복되는 필드 이름과 빈 답글 정보도 줄여 입력을 압축합니다. 전처리 자체에는 AI 호출이 없습니다. 조회 기간·원문 개수·전처리 건수 같은 운영 통계는 요약 답변에 표시하지 않습니다. 입력 한도로 일부 대화가 빠졌을 때만 짧게 안내합니다.

`/ask`는 검색 상위 6개와 같은 채널의 가까운 메시지(시간 차 10분 이내, 각 최대 5개 및 저장된 답글 원문)를 사용합니다. 모든 관련 발언이나 가장 최신 결정이 반드시 검색된다는 보장은 없습니다.

AI에는 긴 Discord 메시지 ID 대신 요청별 짧은 인용번호를 전달합니다. 부분 요약과 최종 답변의 번호를 실제 제공된 원문과 대조한 뒤에만 원문 링크를 만듭니다. 인용번호가 틀리거나 형식이 깨지면 잘못된 링크나 반복되는 미확인 근거 문구를 게시하지 않고 재요청 안내를 표시합니다.

## 질문 채널과 스레드 대화

관리 웹 **봇 설정 → Discord 연결**에서 **수집할 채널 ID**와 **질문할 채널 ID**를 따로 입력합니다. 두 목록은 겹칠 수 없습니다. 환경변수로는 `INDEX_CHANNEL_IDS`와 `QUESTION_CHANNEL_IDS`입니다. 질문 채널을 비워 두면 자동 답변이 꺼지고 기존 슬래시 명령은 유지됩니다.

질문 채널에서는 `/ask`, 봇 멘션, 물음표 없이 메시지만 보내도 공개 스레드를 만들어 답합니다. `C언어 strlen 설명해줘`, `환영 인사 써줘` 같은 일반 요청도 처리하며, 같은 스레드에서 `영어로 번역해줘`처럼 이어서 요청할 수 있습니다. 일반 요청은 원문 검색 없이 답하고, 서버에서 누가 무엇을 말하거나 결정했는지 묻는 질문은 검색한 원문으로 확인합니다. 답변 본문을 바로 표시하며 검색 근거가 없다는 기계적인 제목은 붙이지 않습니다. `/ask`도 `question`만 입력하면 됩니다. 서버 대화에 관한 질문은 검색어를 자동 추출하며, 일반 요청은 원문 없이 답합니다. `query`는 검색어를 직접 지정할 때만 쓰는 선택 항목입니다.

1. 수집 채널에는 참고할 원래 대화를 남깁니다. 기존 기록은 `/index`로 채울 수 있습니다.
2. 질문 채널(요약봇 채널)에 `#개발대화 최근 3일 동안 결정 사항과 할 일을 정리해줘`처럼 실제 채널 태그와 요청을 함께 보냅니다. 봇은 태그한 채널의 최근 대화를 직접 읽고, 요청한 관심사·형식에 맞춰 공개 스레드로 요약합니다. 기본 형식은 `💬 #채널 대화 요약` 제목 아래 중요한 화제 최대 3개를 고른 3~5줄과 원문 링크입니다. 결정·변경, 약속·마감을 우선하며 서론 없이 구체적인 내용부터 씁니다. 일반 질문과 후속 질문은 이전 요약을 반복하지 않고 답부터 1~3문장으로 전달합니다. 한 줄에 핵심 내용 하나를 쓰고 인사·반복 반응은 생략하며, 제안과 확정된 약속을 구분합니다. 일반 답변에는 제목·요약 본문·원문 링크만 표시하고, 일부 원문이 입력 한도로 빠진 경우에만 짧게 안내합니다. 목록·표 등을 명시하면 해당 형식을 따르며, 채팅의 주장과 의견은 검증된 사실로 단정하지 않습니다.
3. 새 스레드에는 숫자 ID 대신 첫 질문을 바탕으로 `일반 · 최근 1시간 대화 요약` 같은 제목을 붙입니다. 제목은 최대 50자이며 별도 AI 호출을 사용하지 않습니다. 같은 스레드에 `담당자도 같이 적어줘`처럼 추가 요청을 보내면 제목을 유지하고 대화를 이어갑니다. 최근 사용자 요청에 태그된 채널·기간을 이어받고 원 질문과 최근 대화 최대 12개(각 1,000자)를 참고합니다. 다른 채널을 직접 태그하면 그 채널로 대상을 바꿉니다.

질문 채널에서는 봇에 **View Channel**, **Read Message History**, **Send Messages**, **Create Public Threads**, **Send Messages in Threads** 권한이 필요합니다. 질문 채널과 근거로 사용할 수집 채널의 **채널 보기·기록 읽기 권한 덮어쓰기**를 동일하게 맞추세요. 봇이 만든 공개 스레드는 질문 채널 구성원에게 보입니다. 더 제한된 채널의 정보를 공개 스레드에 옮기지 않도록 권한 설정이 다른 근거 채널은 제외하며, 기존 `/ask`는 요청자 개인 권한으로 조회합니다. [discord.py Message.create_thread](https://discordpy.readthedocs.io/en/stable/api.html#discord.Message.create_thread)

채널 태그 요약은 기간 표현을 이유로 요청을 거절하지 않습니다. `오늘`, `어제`, `최근 14일`, 특정 날짜·날짜 범위처럼 코드가 해석할 수 있는 기간은 먼저 원문을 잘라 전송합니다. 7일 제한은 없으며 실제 조회는 현재 보관기간 안으로 맞춥니다. `/summary hours`도 최대 8,760시간까지 받고 보관기간 안으로 맞춥니다.

`지난 행사 때`, `점심 무렵`, `지난주 월요일`처럼 코드가 인식하지 못하는 표현, 잘못된 날짜 또는 기간을 생략한 요청은 보관기간 전체를 조회한 뒤 질문 원문·사용자 대화 맥락·현재 시각·시간대·실제 조회 범위를 모델에 함께 전달합니다. 모델이 발언시각을 기준으로 요청에 해당하는 내용을 고르며, 해석이 불가능하면 되묻고 자료가 부족하면 그 한계를 밝힙니다. 날짜 해석만을 위한 추가 모델 호출은 없습니다. 다만 조회 범위가 넓어지면 요약을 위한 분할 호출은 늘 수 있습니다.

현재 `RETENTION_DAYS` 설정과 AI 입력 상한은 그대로 적용됩니다. 입력 상한으로 빠진 원문 건수와 실제 포함된 원문의 시각 범위를 모델에 전달하고, 사용자에게도 부분 요약을 표시합니다. 실제 조회 범위는 모델에 내부 정보로 전달하며 답변 아래에 운영 통계를 붙이지 않습니다. 채널은 최대 3개까지 태그할 수 있고, 미허용 채널이나 권한이 다른 채널로 대체하지 않습니다. 태그 없는 일반 검색 질문은 기존 검색 방식을 유지합니다.

태그 없이 새 질문을 시작하면 기존 검색 기반 대화로 처리합니다. 이 경로는 검색어 추출과 답변 생성으로 보통 Gemini 호출 2회를 사용하며 기존 일일 호출 한도를 공유합니다. “다들 계절이 뭐야”처럼 참여자들의 상황을 묻는 질문도 대화 검색으로 해석합니다. 검색은 핵심어 최대 4개 × 각 상위 3개(`/ask`는 6개)와 같은 채널의 전후 30분 대화(검색 결과별 가까운 61개, 전체 최대 120개 후보)를 사용해 뒤늦은 답변·정정도 함께 확인합니다. 의미/벡터 검색이 아니며 근거가 없으면 추측하는 대신 재질문합니다. 질문 길이는 1,000자, 사용자별 간격은 10초이며 동시에 다른 AI 요청을 처리하고 있으면 스레드에서 재시도를 안내합니다.

질문·봇 답변·스레드 대화는 로컬 인덱스에 저장하지 않습니다. 후속 대화 시 Discord에서 필요한 최근 맥락만 읽으므로 재시작 후에도 봇 소유의 활성 스레드에서 대화를 이어갈 수 있습니다. 잠기거나 보관된 스레드, 다른 사람이 만든 스레드, 봇·웹훅 메시지는 자동 처리하지 않습니다. 편집한 질문에는 자동 재답변하지 않으므로 새 메시지로 질문하세요. 수집 제외 사용자의 질문은 자동 처리하지 않으며, 대화 맥락에서도 해당 사용자의 메시지를 제외합니다. 이미 게시된 봇 답변은 자동 삭제되지 않습니다.

## 6. 동기화·삭제·권한

수집 중 메시지 수정은 원문과 FTS 인덱스를 함께 갱신합니다. 삭제 이벤트에는 삭제 표시를 기록해 늦게 도착한 저장 작업이 해당 메시지를 되살리지 않도록 했습니다.

시작 시와 실행 중 15분마다 **최근 3일 전체**를 페이지 끝까지 수집·재확인합니다. 보관 설정이 3일보다 짧으면 해당 설정을 우선합니다. `.env`의 `SYNC_MESSAGE_LIMIT`는 전체 상한이 아니라 한 번에 읽을 페이지 크기이며 기본 500개, 허용 범위 100~1,000개입니다. 이 범위 안에서는 오프라인 중 발생한 삭제·수정도 보정합니다. 중간 조회에 실패하면 다음 주기에 다시 확인하며 완료로 간주하지 않습니다. 3일보다 오래된 저장 기록은 보관기간까지 유지되며 `/index`로 추가 수집·재확인할 수 있습니다. `/search`와 `/ask`는 사용자에게 보여주거나 AI에 보내기 전 후보 원문을 다시 가져오며, 조회 실패 시 저장본으로 대체하지 않습니다.

조회 시 사용자·봇 멤버 정보와 채널 권한 덮어쓰기를 다시 가져옵니다. 역할 정의는 Gateway로 갱신되는 Discord 클라이언트 캐시를 사용합니다. 원자적인 권한 스냅샷을 보장하는 시스템은 아니므로 운영 전 역할 변경·채널 숨김 시나리오를 실제 서버에서 테스트하세요. 일반 스레드는 인덱싱하지 않습니다. 질문 채널의 봇 소유 공개 스레드만 대화 대상으로 처리합니다. 공개 답변의 근거 채널은 질문 채널과 모든 역할·멤버의 View Channel/Read Message History 권한 덮어쓰기가 같은 채널로 제한합니다. 실제 열람자가 같아도 권한 설정 방식이 다르면 보수적으로 제외합니다.

SQL에는 서버와 허용 채널 조건이 적용되며 빈 허용 목록은 접근 거부입니다. AI 처리 후에도 접근 가능 채널과 저장된 원문 변경 여부를 다시 확인해, 처리 중 감지된 삭제·수정·수집 제외가 있으면 답변을 폐기합니다. 이미 외부로 전송한 원문이나 사용자가 본 결과까지 소급해서 회수하지는 못합니다.

`/status`의 가장 오래된/최신 저장 시각은 중간 누락이 없다는 증명이 아닙니다. 최근 3일 자동 수집은 지원하지만 인덱싱 완료 구간의 영구 추적·분산 작업 큐는 구현하지 않았습니다.

## 7. 개인정보와 외부 API

보관하는 데이터는 본문, 표시 이름, 작성자/메시지/서버/채널 ID, 작성·수정 시각, 답글 대상 ID입니다. 새 메시지 수집 시에는 보관기간을 검사하며, 만료 기록은 실행 중 15분 주기의 정리 작업으로 제거합니다. 프로세스가 꺼져 있으면 디스크 정리도 재시작할 때까지 중단됩니다.

`/privacy action:optout`은 본인의 활성 DB 원문 및 검색 인덱스를 논리적으로 삭제하고 재수집을 막습니다. 수집 제외에 필요한 서버/사용자 ID는 재허용할 때까지 남습니다. 타인의 인용, 외부 API 로그, 운영자 백업, 이미 전달한 요약까지 삭제하지는 않습니다. Discord 원문을 삭제하는 명령도 아닙니다.

AI를 켜면 선택한 원문·표시 이름·시각·메시지/채널 식별자가 Google Gemini API로 전송됩니다. 기존 OpenAI Python SDK의 Chat Completions 호환 경로를 사용하지만 목적지는 Google입니다. `store=False`를 전송하거나 무보관을 보장하지 않습니다. 적용되는 Gemini 서비스 데이터 처리 약관을 확인하세요. [S6]

봇은 생성 요약을 별도 DB에 저장하지 않습니다. 그 대신 같은 요청에도 API 비용이 다시 발생합니다. 사용자 쿨다운, 전역 동시 AI 요청 1개, UTC 날짜 기준 일일 API 호출 상한을 적용합니다. 상한은 토큰/금액 한도가 아니며 실패한 요청도 호출 예약 수에 포함됩니다. 제공자 측 비용 관리도 별도로 설정하세요.

DB는 기본적으로 평문입니다. 호스트·볼륨·백업 접근 권한과 암호화를 운영자가 관리해야 합니다. SQLite의 논리 삭제나 `secure_delete`만으로 WAL, FTS 내부 기록, 스냅샷, 저장장치에서의 포렌식 복구 불가까지 보장하지 않습니다. 백업을 만들 경우 삭제 요청 반영과 보관기간도 별도로 운영하세요.

채팅 안의 지시는 모델이 수행할 명령이 아니라 분석 데이터로 취급합니다. 모델에는 실행 도구를 제공하지 않으며, 모델이 만든 URL은 제거하고 주어진 원문 ID에 대응하는 링크만 생성합니다. 이러한 조치가 요약의 사실 정확성이나 모든 프롬프트 공격에 대한 완전한 방어를 보장하지는 않습니다.

## 8. Docker 실행

`.env` 설정 후 프로젝트 폴더에서 실행합니다.

```bash
docker compose up -d --build
docker compose logs -f --tail=100
```

Gateway 방식이므로 외부에 HTTP 포트를 열지 않습니다. DB는 이름 있는 볼륨 `chat_data`에 저장하며, 컨테이너 재시작 때 유지합니다. 여러 컨테이너가 같은 SQLite 파일을 동시에 사용하도록 확장하지 마세요.

```bash
docker compose down
```

위 명령은 봇을 중단합니다. `down -v`는 저장 볼륨까지 지우므로 데이터와 수집 제외 목록을 모두 폐기하려는 경우에만 사용하세요. 새 설정을 반영하려면 컨테이너를 다시 생성해야 할 수 있습니다.

의존성 파일은 호환 버전 범위를 지정한 시작용 구성이지 고정된 배포 잠금 파일은 아닙니다. 운영 환경에서 통합 검증 후 버전을 고정해 배포하세요.

## 9. 로컬 검증과 실제 서버 점검

외부 연결 없는 검색 데모:

```bash
python demo.py
```

의존성 설치 후 테스트와 구문 검사:

```bash
python -m unittest discover -s tests -v
python -m compileall -q chatbot
```

테스트는 한국어 검색, 채널/서버 필터, 기간 필터, 갱신/삭제, 재수집 방지, 수집 제외, 입력 한도, API 비활성 기본값, 분할 요약 호출 및 원문 링크 처리를 확인합니다. AI 테스트는 모의 응답을 사용합니다.

운영 전 비공개 테스트 서버에서 다음을 직접 확인하세요.

- `/index`로 과거 텍스트를 넣고 `/search`에서 원문 링크 확인.
- 본문 수정 후 예전 단어가 사라지고 새 단어가 검색되는지 확인.
- 개별/일괄 삭제, 재시작 중 삭제, 오래된 구간 재인덱싱 확인.
- 다른 역할 계정으로 숨긴 채널의 검색 결과·요약이 노출되지 않는지 확인.
- `/privacy optout` 후 `/index`를 반복해도 본인 기록이 돌아오지 않는지 확인.
- API 활성화 후 요약 원문 근거, 긴 대화의 부분 요약 표시, 한도 초과 오류 확인.

## 10. 확장 방향

먼저 실제 채널에서 검색 품질·인덱스 크기·조회 지연을 측정하세요. 의미가 비슷한 표현을 찾는 요구가 생기면 대화를 문맥 단위로 묶고, 별도의 임베딩 인덱스를 추가하는 방향으로 확장할 수 있습니다. 확장 시에도 서버/채널 권한 필터를 검색 전에 적용하고, 원문 수정·삭제 시 파생 인덱스와 요약까지 무효화해야 합니다.

정기 일일 요약 게시, 스레드 수집, 벡터 검색, 다중 서버, 분산 작업 큐는 현재 소스에 포함하지 않았습니다. 로컬 봇 관리 웹은 아래에서 사용할 수 있습니다.

## 로컬 봇 관리 웹 (Mac)

기존 requirements만 사용하며 프런트엔드 빌드 도구나 추가 패키지는 필요하지 않습니다. 가상환경과 기존 패키지를 준비한 뒤 프로젝트 폴더에서 실행하세요.

```bash
.venv/bin/python -m chatbot.admin
```

브라우저에서 [관리 화면](http://127.0.0.1:8765)을 엽니다. 포트를 바꾸려면 `--port 8766`을 추가합니다. 한 프로젝트에서는 하나의 관리 서버만 실행할 수 있습니다.

기본 로컬 실행은 개인용 페이지로, 로그인 없이 바로 사용합니다. Hermes의 Tailscale Serve 배포는 별도 관리자 인증을 사용합니다.

- **대시보드:** 관리 화면에서 시작한 봇의 연결 상태, 허용 채널에 저장된 메시지 수, 최근 7일 집계, UTC 일일 API 호출 수.
- **수집 채널:** 수집/질문 채널을 구분해서 표시하며, 수집 채널 ID별 저장 건수와 최근 동기화 시각을 확인합니다. 원문과 작성자는 웹으로 노출하지 않습니다. 동기화 표시는 전체 기록 수집 완료를 뜻하지 않습니다.
- **봇 설정:** Discord 토큰·서버 ID·수집 채널·질문 채널, Gemini 키·모델·AI 활성화, 보관기간·호출 한도·동기화 페이지 크기·시간대.
- **운영 기록:** 현재 관리 세션의 최근 100개 안전한 이벤트. 공급자 오류 원문·API 키·채팅 원문은 기록하지 않습니다.

처음에는 **봇 설정**에서 연결 정보를 저장하세요. `Discord Developer Portal`에서 Message Content Intent와 채널 권한을 준비한 뒤 **봇 시작하기**를 누릅니다. AI를 사용하려면 키 입력과 별도로 **AI 요약·질문 답변 사용**을 켜야 합니다. 키가 저장되었다는 표시는 유효성 검증이나 과금 계정 확인을 의미하지 않습니다.

설정은 로컬 `.env`에 원자적으로 저장되고 파일 권한은 0600입니다. 빈 키 입력은 기존 값을 유지합니다. 봇 실행 중에는 설정을 저장할 수 없으므로 중지 → 설정 저장 → 시작 순서로 변경하세요. 이 관리 화면이 실행한 자식 봇에는 저장된 `.env` 값이 상속 환경변수보다 우선 적용됩니다. 직접 `python -m chatbot.bot`으로 실행할 때는 기존 dotenv 동작에 따라 셸 환경변수가 우선할 수 있습니다.

관리 서버는 `127.0.0.1`에만 바인딩합니다. 기본 로컬 모드는 같은 기기의 신뢰할 수 있는 사용자용이며, Host/Origin 검사와 CSRF 토큰으로 브라우저의 교차 출처 변경을 차단합니다. Tailscale Serve 원격 접속에는 `--public-origin`과 `--auth-file`을 함께 지정하는 인증 모드를 사용합니다. 이 모드는 모든 화면과 API에 HTTP Basic 인증을 요구하며 지정한 HTTPS 주소의 Host/Origin을 검사합니다. 설정 방법은 `deploy/HERMES.md`를 참고하세요.

봇은 자동 시작되지 않습니다. 웹에서 시작한 프로세스만 제어하며, 다른 터미널에서 띄운 봇을 발견하거나 종료하지 않습니다. 동일 DB를 쓰는 봇을 별도로 동시에 실행하지 마세요. 관리 서버를 Ctrl+C로 종료하면 관리 중인 자식 봇도 종료합니다. 브라우저 탭을 닫는 것만으로는 서버나 봇이 종료되지 않습니다.

보관기간을 줄이거나 서버·허용 채널을 바꾸면 다음 봇 시작 시 기존 정리 규칙에 따라 범위 밖 저장 메시지가 삭제될 수 있습니다. 웹에서 이 변경을 저장할 때 확인 안내가 나타납니다. 웹은 DB 스키마를 변경하지 않습니다.

검증 범위: 로컬 HTTP·설정 저장·키 비노출·프로세스 제어·저장소 범위 테스트와 브라우저 UI 확인을 수행했습니다. 실제 API 키/Discord 토큰을 넣은 종단 간 연결은 별도 검증이 필요합니다. `TEST_REPORT.md`를 확인하세요.
